Reports Spring's self-invocation pitfall: calling a @Transactional method from another method of the same class via this (or with no qualifier). 
class OrderService {
    public void process(Order o) {
        save(o);            // bypasses the proxy — @Transactional ignored
    }
    @Transactional
    public void save(Order o) { ... }
}

Spring's transaction management is proxy-based: external callers go through a generated proxy that opens the transaction, but an internal call reaches the target instance directly, so the annotation's settings (propagation, isolation, rollback rules, REQUIRES_NEW, …) silently do not apply.

Fixes: move the transactional method to a separate bean, inject a self-reference and call through it, or make the calling method itself transactional. A call routed through a different bean reference is not flagged because it passes through the proxy.

Only method-level @Transactional callees are reported, to avoid noise from every internal call inside a class-level @Transactional service.

By default RepoBuddy runs in panel-only mode: these findings appear in the RepoBuddy Issues tab, the editor banner, and the status-bar counter rather than inline. Disable panel-only mode under Settings | Tools | RepoBuddy to see them as ordinary editor warnings.
