Detects the classic N+1 query pattern: accessing a lazily-loaded JPA association on a loop variable inside a for-each loop. Each iteration triggers a separate SELECT, so a list of N entities causes N + 1 queries. 
for (User user : users) {
    user.getAddresses().size();   // lazy @OneToMany loaded once per user
}

The inspection is intentionally conservative to avoid false positives. It fires only when:

  • the loop variable's type is an @Entity, and
  • the accessed property is a clearly lazy association — @OneToMany/@ManyToMany (lazy by default), or @ManyToOne/@OneToOne declared with fetch = FetchType.LAZY.

Associations annotated with a sufficiently large Hibernate @BatchSize are ignored (configurable threshold). Safe accesses such as getId() are never reported.

No automated fix is offered because the correct remedy lives in the query that loads the collection — add a JOIN FETCH or an @EntityGraph. Indexed for/while loops and stream pipelines are not yet analysed.
