Reports methods that write to the database without transactional context.
  • @Modifying without @Transactional – a Spring Data @Modifying query method that is neither annotated @Transactional nor declared in a @Transactional class throws at runtime unless every caller already runs inside a transaction.
  • JPA / Hibernate / JDBC writes – a method body that calls JPA persist, merge, remove, flush, or Query.executeUpdate(); a Hibernate Session mutator (save/update/saveOrUpdate/delete); or a JdbcTemplate update/batchUpdate/execute outside a transaction. JPA/Hibernate writes throw TransactionRequiredException; JDBC writes auto-commit individually.
  • Repository write calls – a method that calls repository save/delete/update operations without @Transactional; important when several writes must commit atomically. Enabled by default; disable it via the inspection options if it is too noisy.

A quick-fix annotates the method with @Transactional. Both Spring and Jakarta/javax @Transactional annotations are recognised as satisfying the requirement.

Private methods are ignored by default because Spring's proxy cannot apply @Transactional to them. Static methods that write are reported with a distinct message and no quick-fix, since Spring cannot proxy a static method — the remedy is to refactor to an instance method or manage the transaction manually.

By default RepoBuddy runs in panel-only mode: these findings appear in the RepoBuddy Issues tab, the editor banner, and the status-bar counter rather than inline. Disable panel-only mode under Settings | Tools | RepoBuddy to see them as ordinary editor warnings.
